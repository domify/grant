# Grant native iyi port

## Port loop rules (read first)

These rules govern every Codex run started by `bin/port-loop`.

- Read `port/HINTS.md` first if it exists; it carries the supervisor's guidance.
- The only valid completion condition is `bin/port-check` exiting 0. Its last
  line is `PORT <done>/<total> AREA <area> OK|FAIL`.
- Scope is the SQLite adapter. PostgreSQL/MySQL entries are already `excluded`
  by the generator; everything else in `port/coverage.yml` must reach `done`.
- Never end with a list of remaining work or "recommended next steps". If work
  remains, take the next `todo` entry in priority order and continue.
- Never modify, delete or skip original tests under `crystal-upstream/`, never
  weaken assertions, never mark an entry `excluded`.
- Hard items are not optional: split them into child entries
  (`{id: <parent-id>.1, kind: child, area: ..., name: ..., iyi_ref: null, status: todo}`
  directly after the parent line) and continue. A parent is done only when all
  children are done.
- After each entry or small group: run `bin/port-check --fast` (full
  `bin/port-check` before finishing a run), update `port/coverage.yml`, update
  the status docs briefly (`doc/PORTING.md`, the relevant `doc/*.md`), git commit.

### Coverage map

`port/coverage.yml` is generated by `ruby port/coverage.rb generate` (one line per
entry: one per original `it`/`pending` example and one per public source method
or macro). Only `status`, `iyi_ref` and child entries may be edited; regenerating
keeps them. To mark an entry `done`:

- Port the behavior to native iyi and translate the original example's
  assertions into a `*_test.iyi` program (all its assertions, same scenario).
- Put a comment `# cov: <id>` (several ids allowed) in that test file next to
  the translated case. The test file must pass in `bin/port-check`.
- Test entries: `iyi_ref` is the test file path, e.g. `transaction_test.iyi`.
- API entries: `iyi_ref` is `<file>.iyi#<symbol>` naming the native
  implementation, and some passing test must carry the entry's `cov:` marker.
- Existing native tests may already cover an entry: verify the behavior against
  the original spec, add any missing assertions, then add the marker. Do not
  redo finished work.
- No `TODO`/`FIXME`/`pending`/`skip` comments and no `exit 0` in test files.

Set `IYI_CACHE_DIR=$PWD/.iyi-cache` (the loop does this); `/tmp` is a small
tmpfs. `bin/port-check` uses `IYI=/home/priit/contribute/iyi/bin/iyi` (the
patched compiler) when present.

### Priority order (order, not scope: every area must reach done)

1. Finish transaction callbacks: parity check against original behavior,
   artifact tests, status docs update (area `transactions`; currently
   `transaction_callback_test.iyi` does not build).
2. Query API: comparisons/OR, then projections and aggregations, then JOINs
   (area `query`).
3. Model association API, then autosave and nested-attributes behavior
   (area `associations`).
4. Dirty-state integration with transactions, then optimistic partial updates
   (area `dirty_state`).
5. Everything else in `port/coverage.yml` (area `other`). Use the real
   consumer `/home/priit/apps/ct` (read-only; see its `models/` and `*.iyi`)
   only to decide which remaining items go first.

## Background

Port the behavior of `crystal-upstream/` to native iyi following the
language's philosophy. Read `README.md`, `doc/PORTING.md`, and the current files
before editing. Read `UPSTREAM.md` for the reviewed source commit and update workflow.
Native code belongs at the repository root. Crystal source is imported only
under `crystal-upstream/`; read its `CLAUDE.md`, relevant source, and focused
specs as reference. Do not hand-edit the imported tree. Use the explicit-source
`scripts/update-crystal-upstream.sh` to import updates; port behavior separately.

Keep public model/association API names and supported behavior close to Crystal
Grant wherever native iyi permits it, reducing changes for Rails and Amber v2
ports. Add convenience aliases rather than replacing compatible APIs. Document
necessary differences such as explicit imports, caller-owned context and error
unions; unsupported source behavior must fail explicitly.

Native library code must compile without `--crystal` or a Crystal ORM bridge.
Use explicit imports, fully typed public APIs, sealed record types, and local
trait implementations. Preserve behavior with meaningful parity cases; adapt
APIs where class reopening, global macros, or exception unwinding conflict with
native iyi. Use error union values and implement the compiler's `Error` trait.

The source Grant is a large ORM, not just SQLite CRUD. Do not claim full parity
from the core tests, copied source files, or the automated migration candidate.
The rejected migration experiment is not library code. The canonical native
checkout is `/home/priit/contribute/grant`; the earlier `~/apps/grant-iyi`
copy is superseded. Update the source inventory and porting status
when a feature is implemented and verified.

The native API currently consists of a `Database` trait, C-backed SQLite and
PostgreSQL adapters, immutable lazy queries, `Mapping(T)`, `Repository(T)`,
error unions, nested transactions/savepoints, explicit `UnitOfWork` sessions,
lifecycle hooks, validation rules, normalization plans, dirty snapshots, schema
definitions and SQL migrations. These feature ports are partial; consult
`doc/PORTING.md` and `doc/ARTIFACT-ISSUE.md` before assuming complete parity. The app supplies its typed record and
mapping. Neither a global model registry nor an inherited macro DSL is used.
Consumer web handlers and RPC handlers should call the same model services.

Repository.update_changed consumes explicit loaded attributes or State(Value)
baselines, runs normal callbacks and skips UPDATE/timestamp reads when clean.
Caller-owned dirty state is not automatically advanced before an outer commit.
Mapping.readonly_attributes and timestamp creation columns protect repository
updates. This partial API does not add optimistic version guards; keep protected
services on Optimistic(T). See doc/PARTIAL-UPDATES.md.

SQLite schema edits use AlterTable and explicit ddl_transaction(rebuilds: true)
ownership; rebuilding inside a foreign-key-enabled outer transaction is rejected.
Definition supports composite table keys and named Check/Unique/Reference
constraints. These do not add composite model IDs to Repository. Named table
constraints can be edited, including named inline removal and selection of
CHECK/UNIQUE/foreign-key constraints by expression/ordered columns. Primary keys
and other named column clauses require separate APIs.
Dumper/Snapshot captures only the SQLite main schema, preserving catalog SQL and
native migration checksums. Replacement is explicit and drops snapshot data.
See doc/SCHEMA.md. Keep alteration, constraints, snapshots and the generated
schema factory in the source-free artifact gate.
Catalog provides live SQLite tables/keys/checks/uniques/foreign-key/index metadata,
including inline constraints and expression markers. Column metadata includes
declared families/length/precision/scale, affinity, positions and rowid aliases;
it does not infer mappings or enforce sizes. Main-schema metadata cannot be
shadowed by temporary tables. Collation/comment metadata and DDL size options
remain pending.

Mappings declaring a normalization Plan must implement with_attributes to rebuild
their sealed records. Repository normalization runs before validation; query
arguments use only unconditional rules. Hydration bypasses normalization.
Configure plans before use. See doc/NORMALIZATION.md for the explicit assignment
boundary and raw-query behavior.

Additional scalar validators are in `grant/validators.iyi`: numericality, format,
acceptance and `When` with a typed `Condition`. Conditions inspect explicit
attributes/context. See `doc/VALIDATION.md` for semantics and unported validators;
dynamic comparison operands use `DynamicNumericality` and typed `Operand`
policies in `grant/dynamic_validation.iyi`. CheckedRules propagates operand
evaluation failures separately from validation issues. SQLite uniqueness lives in
`grant/database_validation.iyi`: propagate SQL failures as `DatabaseError` and
back validation with an appropriate unique index. Context-aware mappings override
`validate(record, context)`; repository update contexts supply the actual persisted
ID so nil input IDs cannot incorrectly fail self-exclusion.

Current user scope is SQLite only: implement and verify SQLite behavior first.
Keep the existing PostgreSQL adapter, but defer PostgreSQL development and live
verification until the user expands scope. The default check runner excludes
the PostgreSQL test. SQLite is the local behavioral test target. PostgreSQL connection failure is
covered; live PostgreSQL CRUD remains unverified. Tests use disposable data.
Never run the original entire Crystal spec suite in one compilation: it can
require around 20 GB RAM. For original parity reference runs, use focused specs
or the source project's grouped runner in a separate writable checkout.

Run the native test programs listed in README after appropriate changes and
check formatting with `iyi fmt --check grant grant.iyi *_test.iyi`. An artifact
build must also work for APIs crossing modules. Use a writable `IYI_CACHE_DIR`
when needed; do not repurpose HOME. There are no runtime dependency shards;
link the system SQLite/libpq libraries for the relevant adapter.

A mutable connection is owned by one request/task at a time. Pooling,
concurrent scheduling, association inverses/caches/through/polymorphism and the
other remaining features listed in `doc/PORTING.md` are still pending; do not assume
support. Do not silently coerce exact numeric values to floats or substitute
fake successes for unsupported operations.

SQLite `Binary` values bind as BLOB and are copied on decoding. Empty BLOB is
distinct from NULL. Do not coerce arbitrary bytes through text encoding. The
PostgreSQL adapter rejects Binary binding until its port is resumed.

Optimistic locking is an explicit Optimistic(T) repository wrapper with a
Version(T) policy and an Int64 stored column. Route protected writes through it;
plain repository/raw writes do not have a version guard. Use bound where_stored
predicates for stored metadata such as lock versions. See doc/LOCKING.md.

Timestamps(T) is registered on BeforeCreate/BeforeUpdate with an explicit UTC
Clock and mapping.with_attributes. It preserves explicit create timestamps,
stamps updated fields on update, and stores exact UTC text/date values at the
declared precision. Touch and atomic optimistic touch are implemented; deferred
touch/no-op-save/timezone behavior is not complete yet; see
doc/TIMESTAMPS.md. Keep timestamp and locking artifact consumers in the gate.

Around(T) callbacks wrap validation/save/create/update/destroy with typed
single-use Continuation(T) values. Halts, swallowed errors, duplicate calls and
panics trigger rollback; escaped continuations are closed. See doc/LIFECYCLE.md.
Exact Decimal/Date/DateTime values bind as text on SQLite. Decimal schema columns
must use TEXT to avoid numeric affinity loss; decode scalars explicitly in the
mapping and never reconstruct exact decimals from Float64. See doc/SCALARS.md.
DecimalPolicy separates assignment scale/optional precision checks from exact
hydration. Mappings invoke assignment explicitly and preserve legacy stored
values when hydrating. Exact decimal SQL ordering/ranges/aggregation is pending.

Bulk.Writer performs SQLite insert/skip/upsert batches with real returned rows,
bind-cap-aware atomic chunking, explicit readonly/scope/timestamp metadata and
guarded scope conflict updates. It bypasses model callbacks, validation and
normalization; supply stored values. Partial/expression targets, custom fragments,
model converter inference and bulk optimistic guards remain pending. See
doc/BULK.md. Keep bulk, partial-update and decimal-policy artifact consumers in
the gate. PostgreSQL bulk development remains deferred.

BelongsToWriter(O, T) uses an application Reference(O) and explicit staged
Assignment(O, T). New targets are saved before owners in one shared UnitOfWork;
saved targets require autosave: true to write pending changes. create_target
saves only the target. Association inverses and general recursive autosave are
still pending. See doc/ASSOCIATIONS.md.

Direct collection writes use `CollectionWriter(T)` and an application-owned
`Link(T)` implementation. New records and attachments run repository callbacks;
nullify/delete removals are set-based and skip callbacks, while destroy runs
callbacks. Collection operations use savepoints inside an outer unit of work.
`replace_one` implements direct has-one replacement and `remove_all` clears a
scoped collection. Register `Dependency(O, C)` on the owner's BeforeDestroy
pipeline for nullify/delete/destroy/restrict behavior; owner and child repos
must share the same UnitOfWork instance. Repository writes use nested savepoints.
Unsaved-owner staging and association-specific hooks remain pending. See
`doc/ASSOCIATIONS.md`.

The subtree bootstrap uses local commits on `feature/phase-0-native-iyi`, keeping
original Crystal history. Do not push or change public default branches without
user instructions. Keep source imports and native changes in separate commits.

Source-free artifacts require iyi commit a03fc3438 plus the local compound
witness-reference fix preserved in scripts/compiler-witness-union.patch. Use
IYI=/home/priit/contribute/iyi/bin/iyi with scripts/check.sh until the installed
compiler includes it. The gate must remain enabled and exercise model/lifecycle,
normalization, uniqueness, dependency and binary consumers. Do not introduce
synthetic witness declarations in application code as a workaround. See
doc/ARTIFACT-ISSUE.md for the diagnosed ABI regression and fix.
